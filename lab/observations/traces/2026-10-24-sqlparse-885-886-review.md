## Diagnosis (stronger than the build notes)

Both crashes are symptoms of **grouping** producing malformed trees. The filters are not the cause.

- **#885.** `( AS )` parses to `Parenthesis > Identifier('( AS )')`: alias grouping swallows both
  parentheses into one Identifier. The Parenthesis then has a single direct child, so `tokens[1]`
  fails. `(::)` produces the same shape, which is the trigger in earlier PRs #862/#864.
- **#886.** In `CASE 'a' := WHERE END ...`, the WHERE clause takes `END`. The Case group has no direct
  `END` child, so `token_next_by` returns `None` and `token_index(None)` raises.

The patch adds guards in the filters, so malformed input comes back unformatted instead of raising.
That is the same choice all four earlier PRs made. A maintainer could prefer to fix grouping
instead. The PR text should say so plainly and offer to.

## Changes made (reviewed patch)

1. **Third guard `> 1` changed to `> 2`.** With exactly two children, `tokens[-2]` is the opening token,
   not a body. The loops above already use `> 2`, and so did #864. This does not change behaviour
   on any input found, but it keeps the meaning consistent.
2. **`(::)` added as a parametrized case of the #885 test.** Same code path, a second real trigger.
   It fails on master.
3. **One-line comments at both guards naming the issue.** Without them, the next reader cannot see
   why a parenthesis would lack children.
